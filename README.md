# NeilMania — MVP для Татьяны

Комсомольск-на-Амуре, UTC+10. Django 5.2, PostgreSQL для рабочего запуска, адаптивный PWA-интерфейс для телефона и компьютера. Шаг начала записи — 15 минут. Длительность визита равна сумме выбранных услуг. Цен в приложении нет.

## Что работает

- Календарь на неделю с выбором дня и произвольной даты.
- Недельный график и исключения для конкретных дат: выходной, короткий или дополнительный день.
- Личные дела, включая несколько дней: название видно только мастеру; время недоступно для клиентской записи.
- Несколько услуг за визит, изменение длительности, скрытие услуг без порчи истории.
- Самостоятельная заявка клиентки, ручное подтверждение/отклонение, ввод записи мастером.
- Запрос отмены/переноса; старая запись сохраняется до одобрения. Новое время повторно проверяется при одобрении.
- Клиентки: имя, нормализованный российский телефон, заметки, история. Существующие карточки не перезаписываются публичными заявками.
- Секретная ссылка на статус одного визита: без телефона, заметок и истории других визитов.
- Шесть палитр: Пудра, Шалфей, Лаванда, Песок, Океан, Графит. Палитра сохраняется на устройстве.
- Оповещения в приложении, напоминания за час и Web Push с повторной доставкой общего сигнала без личных данных.
- Зашифрованная логическая резервная копия и восстановление в пустую базу.
- Manifest, иконки, отдельный экран отсутствия интернета. Персональные данные не кешируются для офлайн-работы.

## Быстрый запуск на Windows 11

Самый простой способ: дважды щёлкни **Start NeilMania.cmd**. При первом запуске он создаст локальное окружение, установит зависимости, подготовит демонстрационную базу и откроет браузер. Консоль нужно оставить открытой; Ctrl+C останавливает приложение. Если порт 8000 уже занят, выбирается следующий свободный. Существующие процессы не завершаются. При первом запуске нужен интернет для загрузки пакетов.

Этот способ предназначен только для вымышленных данных с SQLite; публичная форма открывается только в процессе локальной демонстрации. Для PostgreSQL и рабочего сервера используй разделы ниже. Запускатор не устанавливает службу и не меняет настройки Windows.

Для просмотра достаточно Python 3.10–3.13. Проверено в этой среде на Python 3.10.11; существующий Python не обновлялся. Для нового рабочего сервера выбери поддерживаемую версию Python и повтори тесты.

Открой PowerShell в папке проекта:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python init_local.py
.venv/Scripts/python manage.py migrate
.venv/Scripts/python manage.py setup_studio
.venv/Scripts/python manage.py createsuperuser
.venv/Scripts/python manage.py runserver 127.0.0.1:8000 --noreload
```

Если `.env` уже существует, `init_local.py` его не меняет. `.env` содержит секреты: не отправляй его в чат, репозиторий или архив проекта.

Открой `http://127.0.0.1:8000/studio/`. Публичная запись по умолчанию выключена. Для локальной проверки на вымышленных данных поставь `PUBLIC_BOOKING_ENABLED=1` в `.env` и перезапусти сервер.

Для демонстрационного наполнения вместо настоящих клиенток:

```powershell
.venv/Scripts/python manage.py seed_demo
```

Команда разрешена только при `DEBUG=1` и SQLite. Вход: `demo`, пароль `NailBook-demo-2026!`. Это общедоступный демонстрационный пароль, **никогда не используй эту учётную запись в рабочей базе**. Две вымышленные записи создаются на следующий день. Рабочую базу создавай отдельно с новым пользователем.

`start-demo.ps1` автоматизирует установку и запуск на Windows. Если политика PowerShell не позволяет запуск скрипта, используй команды выше; менять системную политику не требуется.

## PostgreSQL

SQLite здесь только для знакомства и однопользовательской локальной проверки. При `DEBUG=0` приложение запрещает запуск с SQLite. Защита от параллельных пересекающихся записей использует `select_for_update` на единственной строке Studio, которую берут все операции изменения календаря. Записывать прямо в таблицы в обход бизнес-логики нельзя.

### Установленный PostgreSQL

Создай отдельную базу и пользователя NeilMania, заполни в `.env` `PGDATABASE`, `PGUSER`, `PGPASSWORD`, `PGHOST`, `PGPORT`, поставь `DEMO_SQLITE=0`. Затем:

```powershell
.venv/Scripts/python manage.py migrate
.venv/Scripts/python manage.py setup_studio
.venv/Scripts/python manage.py createsuperuser
.venv/Scripts/python manage.py test booking
```

Тестовому пользователю базы нужно право создавать временную тестовую базу. Рабочему пользователю это право не требуется. Не выдавай приложению роль суперпользователя PostgreSQL. В этой сессии полный набор из 36 тестов прошёл на изолированной PostgreSQL 17.11, включая одновременные заявки и восстановление копии. Демонстрационный сайт при этом остаётся на отдельной SQLite.

### Docker Compose

Docker не обязателен. На этом компьютере он не установлен, конфигурация не запускалась. Файл `compose.yaml` содержит PostgreSQL 17, приложение и обработчик оповещений приложения. Не использовать демонстрационную базу в рабочем запуске.

```powershell
docker compose up -d db
docker compose run --rm web python manage.py migrate
docker compose run --rm web python manage.py setup_studio
docker compose run --rm web python manage.py createsuperuser
docker compose up -d web
```

PostgreSQL хранится в именованном томе и не публикует порт в интернет. Веб-сервис доступен только на `127.0.0.1:8000` хоста. `docker compose down -v` удалит базу — не выполняй его для рабочего проекта.

## HTTPS, iPhone и синхронизация

Облачная синхронизация означает, что телефон и компьютер обращаются к **одному Django-серверу и одной PostgreSQL**. Календарь, заявки и экран статуса обновляются при открытии и раз в 60 секунд на активном экране. Это не отдельный платный сервис. Офлайн-редактирования и разрешения конфликтов офлайн в MVP нет.

Для реального внешнего доступа необходимы сервер в РФ, постоянный адрес и HTTPS. Перед включением:

1. Создай отдельную PostgreSQL, нового мастера с сильным паролем; демопользователя не переносить.
2. Укажи `DEBUG=0`, `DEMO_SQLITE=0`, случайный `SECRET_KEY`.
3. В `ALLOWED_HOSTS` укажи точное имя сайта, а в `CSRF_TRUSTED_ORIGINS` — `https://имя-сайта`.
4. Настрой HTTPS-прокси, например по `Caddyfile.example`, и `TRUST_PROXY=1` **только** если к Waitress обращается исключительно доверенный локальный прокси. Не открывай Waitress наружу напрямую.
5. Прокси должен перезаписывать `X-Forwarded-Proto`. Не журналируй пути `/s/…`, query string и тела форм: клиентская ссылка даёт доступ к записи.
6. Для установленного PostgreSQL: `manage.py collectstatic --noinput`, затем `.venv/Scripts/waitress-serve --listen=127.0.0.1:8000 nailbook.wsgi:application`. В Docker статика собирается при сборке образа.
7. Запусти `manage.py check --deploy` с рабочими настройками. Проверь HTTPS, доступы, cookies, резервное восстановление и запись с двух устройств.
8. На iPhone открой HTTPS-сайт в Safari → «Поделиться» → «На экран Домой», при наличии включи «Открывать как веб-приложение». App Store и Apple Developer Program не нужны для этой модели распространения.

`127.0.0.1` на iPhone — сам iPhone, а не Windows-компьютер. Для телефона нужен доступный адрес сервера. Для полноценного PWA требуется HTTPS; локальный HTTP-предпросмотр на компьютере его не заменяет. Физический iPhone 15 в этой сессии не тестировался.

## Оповещения приложения

Telegram больше не используется. В приложении есть личный центр оповещений, счётчик непрочитанного, напоминания за час и очередь Web Push. В демонстрации обработчик запускается вместе с сервером. Настройка HTTPS, ключей и уведомлений на iPhone: [NOTIFICATIONS.md](NOTIFICATIONS.md).

## Резервные копии

`init_local.py` создаёт случайный `BACKUP_KEY`. Храни копию ключа отдельно от базы и архивов: без ключа восстановление невозможно.

```powershell
.venv/Scripts/python manage.py backup --output backups/nailbook-2026-10-11.nbak
```

Копия шифруется Fernet (аутентифицированное шифрование) и содержит приложение, пользователей с хешами паролей и группы. Сессии, временные ограничения частоты, `.env`, исходники и журналы в неё не входят. Это логический экспорт Django, не побитовая копия PostgreSQL и не PITR. На время копирования останови административные изменения пользователей и рассылку уведомлений; календарные изменения блокируются командой.

`backup-daily.ps1` создаёт копию с датой. Для автоматизации создай ежедневную задачу Windows Task Scheduler, запускающую этот файл; укажи папку проекта как рабочую. Для контейнера запускай `backup` планировщиком хоста с примонтированной папкой резервных копий. Планировщик в этой сессии не создавался.

Храни минимум две копии на разных носителях **в РФ**, с ограничением доступа. Копия на том же диске не защищает от его отказа. Срок ротации предлагается 30 дней; очистку выполняет оператор по утверждённому регламенту, скрипт ничего сам не удаляет. Шифрование не заменяет локализацию и организационные меры.

Восстановление — в новую пустую базу:

```powershell
# В .env сначала укажи НОВУЮ пустую базу и прежний BACKUP_KEY.
.venv/Scripts/python manage.py migrate
.venv/Scripts/python manage.py restore_backup backups/nailbook-2026-10-11.nbak
```

Не запускай `setup_studio` или `createsuperuser` перед восстановлением. В непустую базу команда откажется писать. После восстановления проверь клиенток, историю, расписание и доступ мастера. Если после даты копии были обращения на удаление, повторно исполни их до открытия доступа.

## Ограничения MVP

- Один мастер, один часовой пояс (Комсомольск-на-Амуре); смена города в настройках меняет подпись, не часовой пояс.
- Ожидающая заявка удерживает время до решения мастера; автоматического истечения нет.
- Телефон нормализуется, но не подтверждается SMS. После подтверждения мастером одинаковый телефон связывает записи с карточкой. Для номера семьи или смены владельца нужна ручная проверка; не подтверждай подозрительные заявки.
- Секретная ссылка — bearer-доступ: владелец ссылки может запросить изменение. Не отправляй её посторонним, не добавляй внешнюю аналитику.
- Ограничение частоты запросов по `REMOTE_ADDR` — базовая защита. За прокси все клиенты могут иметь общий адрес; перед публичным запуском настрой доверенную обработку клиентского IP на прокси/сервере и проверь лимиты. Нельзя просто доверять произвольному `X-Forwarded-For`.
- Недельный график поддерживает один рабочий промежуток в день; перерывы добавляются личными делами. Изменение графика не удаляет существующие записи.
- Палитра хранится на устройстве, между устройствами не синхронизируется.
- Смена пароля, восстановление по логину и почте, экспорт данных и удаление клиентского аккаунта реализованы. Для доставки писем нужен SMTP; он пока не подключён. Подробности: [ACCOUNT-AND-SHARING.md](ACCOUNT-AND-SHARING.md). Записи и контакты у мастера при удалении аккаунта сохраняются; их очистка и сроки резервных копий требуют отдельного регламента. Нет 2FA, оплаты, SMS и мультиарендности. Административный сброс пароля — локальная команда `manage.py changepassword имя`.
- Политика и согласие — стартовые шаблоны, требующие заполнения и проверки оператором. Удаление, ответы субъектам и сроки хранения пока обслуживаются оператором по регламенту.

Исследование размещения и персональных данных: [HOSTING-AND-PRIVACY.md](HOSTING-AND-PRIVACY.md).
