# Оповещения NeilMania

Telegram отключён: бот, chat_id и токен больше не используются. Старые строки очереди сохранены при миграции, но не отображаются и не отправляются.

## Уже работает

- Колокольчик и личный центр оповещений `/notifications/`, счётчик обновляется каждые 30 секунд на открытом экране.
- Мастеру: новая заявка, запрос отмены/переноса. Клиентке: подтверждение, отказ, результат отмены/переноса и завершение визита. Запись, созданная самим мастером, не присылает ему лишнее оповещение.
- Напоминания за час до подтверждённого визита и личного дела. Мастер получает напоминания о своих блоках и визитах; клиентка — только о своих визитах и делах. Выполненные дела, отменённые записи и прошедшее время исключены. При включении обработчика позднее напоминание создаётся только для ещё предстоящего события в ближайший час.
- В настройках можно отключить напоминания, подключить push на текущем устройстве, проверить доставку, отключить это или все свои устройства. Не более пяти подписок на аккаунт.
- Push содержит только технический номер оповещения. На устройстве показывается общий текст; имена, телефоны, услуги, названия дел и секретные ссылки в push не передаются. Нажатие открывает личный центр после входа.

Входящие оповещения хранятся на сервере. Это не автономный будильник: для создания напоминаний сервер и обработчик должны работать. При закрытом приложении нужен Web Push. Доставка зависит от сети, разрешений и настроек устройства; это не гарантия сигнала точно в заданную секунду.

## Локальная демонстрация

`Start NeilMania.cmd` запускает сервер и обработчик напоминаний вместе. Закрытие демонстрации останавливает оба процесса. Push без настройки ключей не отправляются; внутренняя лента работает. На `127.0.0.1` нельзя проверить доставку на физический iPhone.

## Подключение push на рабочем сервере

1. Подготовь доступный HTTPS-адрес и PostgreSQL. Отдельная платная служба рассылок не используется, но серверу нужен доступ в интернет.
2. Один раз создай ключи в папке проекта:

   ```powershell
   .venv/Scripts/python manage.py init_push
   ```

   Команда создаёт `.keys/webpush.pem` и выводит публичный ключ и путь к закрытому ключу. Сам закрытый ключ не выводится. Существующий файл не перезаписывается. Не меняй ключи после подключения устройств без плана повторной подписки.
3. Перенеси выведенные значения `WEBPUSH_PUBLIC_KEY` и `WEBPUSH_PRIVATE_KEY` в локальный `.env`; добавь `WEBPUSH_SUBJECT=mailto:реальная-почта-владельца`. Секреты и файл ключа не отправляй в чат. `.keys/` исключена из Git и Docker-образа; сохрани её защищённую копию отдельно от исходников.
4. Перезапусти приложение. Запусти постоянный обработчик:

   ```powershell
   .venv/Scripts/python manage.py send_notifications --loop
   ```

   Либо запускай команду без `--loop` раз в минуту планировщиком. Для PostgreSQL рекомендуется один постоянный процесс. В Compose служба `notifications` включена без профиля; каталог `.keys` примонтирован только для чтения. В контейнере задай `WEBPUSH_PRIVATE_KEY=/app/.keys/webpush.pem`; пользователь контейнера должен иметь доступ на чтение. Сначала выполни миграции, затем запускай обработчик.
5. На iPhone с iOS 16.4+ открой сайт в Safari → «Поделиться» → «На экран Домой». Запусти приложение с иконки → настройки → «Включить уведомления». Разрешение запрашивается только после нажатия. [Требования WebKit](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/).
6. Нажми «Проверить доставку», сверни приложение, дождись сигнала, открой его. Затем проверь реальную заявку с отдельного клиентского аккаунта, подтверждение мастером и напоминание. Физический iPhone и рабочая доставка пока не проверены.

Поддерживаются адреса push-служб Safari/Apple, Chrome/FCM и Firefox/Mozilla. Неизвестные адреса отклоняются; автоматические перенаправления при отправке запрещены. Новый провайдер требует явного изменения разрешённого списка после проверки.

Сбой отправки сохраняет очередь: до восьми попыток, интервал растёт до часа. Старше суток сообщения не отправляются; просроченные/отменённые напоминания и уже прочитанные оповещения также пропускаются. Удалённая браузером подписка (404/410) удаляется из базы. При аварии между отправкой и сохранением результата возможен повтор; одинаковый тег заменяет уведомление на устройстве.

Выход из аккаунта сам по себе не отзывает подписку; общий сигнал может приходить дальше, содержание по-прежнему требует входа. Для общего устройства используй «Отключить здесь». Подписку другого аккаунта нельзя перепривязать; сначала её нужно отключить в прежнем аккаунте либо сбросить разрешение сайта. После «Отключить все устройства» для восстановления на нужном устройстве нажми «Подключить / восстановить».

## Проверка

Автотесты проверяют получателей, доступы, CSRF, повторную доставку, отзыв подписки, отсутствие личных данных в payload, запрет произвольных URL и перенаправлений, отмену устаревших напоминаний и сохранение ленты при ненастроенном push. Сетевой транспорт подменяется: это не подтверждение доставки через Apple.

Push-подписки входят в зашифрованную копию базы; ключ VAPID хранится отдельно. После восстановления старой копии отзови восстановленные подписки, если их разрешения уже не актуальны, и проверь очередь перед запуском обработчика. Технические идентификаторы и использование служб браузеров следует отразить в документах оператора перед рабочим запуском.
